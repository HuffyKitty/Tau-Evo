# Tau-Evo：10 题冻结基线与学习组流程验证

2026-11-27。实验 ID：`75ff4f50b7be40888a1bdfd68b40e75f`。

**结论：冻结组 3/10，学习组 2/10。真实的失败反馈 → Reflect → Compile → 下一批 Skill 注入已验证。这个小样本不能证明 RSI 有效，也不能把两组差异归因于 Skill。**

这是 Evo-Harness 方法在 Tau CodingSession 和 DeepSeek 上的适配验证，不是论文原始模型配置或论文分数的复现。可核验数据见 [JSON 报告](swe-lite-10-2026-11-27.json)，实现与 CI 见 [PR #3](https://github.com/HuffyKitty/Tau-Evo/pull/3)。

**实验条件**

- 数据：`SWE-bench/SWE-bench_Lite`，revision `b0dde1093fe417d83b7184254edf8199c1f0dff5`。在观察结果前，选取 `sympy/sympy` 内按 instance ID 字典序排序的前 10 题。
- 两组使用 `deepseek-flash`、相同题目和顺序、相同 Tau 求解器源码、同一工具 schema 及逐题镜像 digest。工具为容器内的单一 bash 入口。
- 每题最多 20 个模型轮次、300 秒解题时间、每次响应最多 4,096 个输出 token；单条 shell 命令 60 秒。两组分别运行 10 次求解，没有为改善分数重抽样。
- 官方评分器为 `swebench==5.0.2`，在 Linux 容器中调用原版 CLI。最终所有候选补丁统一使用 1,800 秒测试时限。
- 每批 2 题，共 5 批。冻结组始终为空 Skill；学习组在批次边界更新，最后一批不再学习。
- 相同的是**解题预算上限**。学习组另有 Reflect/Compile 开销，下表单独报告；这不是总计算成本严格匹配的实验。

**学习闭环证据**

首批两个失败经过模型 Reflect/Compile，产生 `skill-exact-requested-output-forms` 和 `skill-printer-conditional-output`。首个非空快照为 `2ef2523182d7eae7431354c3478bdd80afa1ec87e8119ff358a54b26debd378b`。

下一批的 `sympy__sympy-11897` 实际选中了这两条 Skill。审计脚本不仅检查 selection 记录，还核对 `system.txt` 的哈希，并确认选中的完整 Skill 正文出现在该次求解的系统提示词中。后续空补丁失败又产生了 `skill-apply-edit-before-finalizing`，已有 Skill 发生了合并与修订。

共执行 9 次学习模型调用，产生 3 次非空快照更新。公开 JSON 中的 `learning_links` 将每次注入关联到更早批次的失败任务、Skill 修订号及正文哈希。审计同时核对官方报告哈希、批内快照一致、镜像 digest 和两组解题参数。

**实施期间发现并修复的问题**

1. Windows 原生运行评分器会将生成的 Linux 脚本写成 CRLF；改用独立 Linux 评分容器后，参考补丁预检通过。
2. 最初 180 秒评分时限连 `sympy__sympy-11870` 的官方参考补丁也跑不完。没有把这次超时作为模型失败学习；在第一次 Skill 激活前，统一采用官方默认的 1,800 秒，用保存的补丁重新评分两组。原 manifest、报告和求解记录保留，调整写入独立的 `grading-policy.json`。1,800 秒下参考补丁通过，候选补丁为真实测试失败。
3. 评分驱动进程在测试超时后可能迟迟不退出；现在保留已写出的官方结果与进程状态，不丢失评分证据。
4. 第三批 Compile 合并时合法引用了目标 Skill 已有的失败来源，原校验器误拒绝。修复后用同一份缓存响应完成编译，没有额外模型调用。每次修改仍须引用当前批次候选，未知来源和未来任务引用会被拒绝。

正式实验前另有 2 题诊断尝试：模型反复寻找上游答案而没有提交补丁，隔离环境阻止其获取答案。加入统一的“依据当前代码修复、禁止寻找 gold/隐藏答案”约束后，重新冻结两组配置。该诊断的 801,247 个 solver token 不计入两组结果，也未生成正式实验 Skill。

**验证与解释边界**

28 项离线 Evo 回归覆盖真实边界；Ruff、mypy、文档构建和完整 Linux CI 均已验证，最终提交状态以 PR 检查为准。真实 Docker/DeepSeek 结果独立于这些离线测试。

样本只有一个仓库的 10 题，没有重复种子或独立保留集。模型使用服务端别名和默认采样，两组跨日期运行，系统提示词中的运行日期、工作目录随运行变化。控制器在流程验证中修复过评分和证据合并边界。因此本次应作为工程流程检查，不应宣称具备严格的因果效果证据。

当前还没有独立保留集上的 Skill 晋升门控，也没有总成本匹配对照。空补丁和轮次耗尽需要先处理；技能的适用范围及选择也需要单独验证。下一步应先固定后续实验协议、加入多仓库与重复运行、成本对照和保留集门控，再扩大规模。

uv run --extra benchmark tau-evo-swe --experiment .tau-evo/reproduction run --arm frozen --api-key-file API_KEY.txt
